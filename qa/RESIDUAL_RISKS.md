## B. QAが検出し、影響が限定的と判断して文書化した項目

### R-04 宣言的権限マップ（permissions.ts）の未適用領域（§3.2）
- **現状**: `field-agents` / `reports` / `sales-staff` / `announcements` / `agencies` の5領域は、`can()` を経由せずロール配列をファイル内に定義している（10ファイル）
- **影響**: 現時点の配列内容は§5.1と一致しており**機能的な権限逸脱はない**（単体テスト`permissions.test.ts`で§5.1全数を検証済み）。ただし仕様変更時に修正漏れが起きうる二重管理
- **推奨**: 5領域を `can()` へ置換し、`tests/unit/permissions-coverage.test.ts` の例外登録を削除

### R-05 permissions-coverage テストの検出パターンが不完全
- **現状**: ハードコード検出の正規表現が `includes(user.role)` 形のみで、`user.role === "Rn"` 形（42箇所 / 13ファイル）を検出しない
- **影響**: テストが緑でもハードコードが残る（偽の安心）。ただしR-04と同様、現在の値は§5.1と一致
- **推奨**: 検出パターンに等値比較形を追加し、ワークフロー分岐のみを理由付きで例外化

### R-06 CSV一括登録の一部が真のトランザクションでない（§3.6）
- **現状**: 販売員IDのCSV一括は単一 `createMany` で原子的。訪販員申請のCSV一括は `StoredFile.createMany` と `FieldAgentApplication.createMany` の2文に分かれており、間で失敗すると誓約書PDFのStoredFile行が孤立して残る
- **影響**: 行の部分登録は起きない（アプリ層で全行検証後に書き込むため）。孤立ファイル行が残るのみ
- **推奨**: `withScopedTransaction()`（実装済み）で包む。孤立StoredFileの定期クリーンアップを日次バッチへ追加

### R-07 一部 server action がエラーを画面に表示しない
- **現状**: `Promise<void>` の action が残存（field-agents / reports / cases の承認・停止・削除系）。権限不足・状態不整合は監査ログ（result=denied）に残るが、画面は無反応
- **影響**: 操作者が失敗理由を把握できない。データ不整合は発生しない（サーバ側で拒否済み）
- **推奨**: 主要なもの（承認・差戻し・削除）から `useActionState` 形へ移行。cases は State 版が実装済みでUI配線のみ

### R-08 接続元IPの信頼設定が必須（§10.1 / 要件1-6, 1-9）
- **現状**: `TRUST_PROXY` / `TRUST_VERCEL_HEADERS` がいずれも無効な環境では、接続元IPが常に `unknown` になる（偽装対策のfail-closed設計の帰結）
- **影響**: その環境では**IP単位のレート制限とIP変化による不正利用検知が機能しない**（アカウント単位のロックは機能する）
- **本番（Vercel）**: `VERCEL=1` により `x-vercel-forwarded-for` が信頼され、実IPが記録されることを確認済み（例: `150.249.201.199`）
- **推奨**: Vercel以外へ移設する場合は必ず `TRUST_PROXY=true` と正しい `TRUSTED_PROXY_HOPS` を設定（README記載済み）

### R-09 `.env.local` の本番DB URLによる事故リスク（運用）
- **現状**: `.env.local` に本番Neonの接続URLがあり、ローカルで起動したバッチが本番DBへ接続しうる。QA中に実際に本番へテスト痕跡が混入した（除去済み）
- **推奨**: `.env.local` から本番URLを削除し、本番接続はVercel環境変数のみに限定する。QA検証は `qa/start-test-server.sh` のように全DB系環境変数を明示指定して起動する

## C. 本環境で検証できずBLOCKEDとした項目（実装は存在）

| 項目 | 理由 |
|---|---|
| セッション絶対24時間 / アイドル60分の実失効 | 実時間経過が必要（実装はDB照会で判定・コード確認済み） |

| Vercel Cronの自動起動 | プラットフォーム側スケジュール（手動実行での動作は検証済み） |
| 第三者脆弱性診断・ペネトレーションテスト | §10.6のインフラ/運用要件（本QAの範囲外） |
| バックアップ・リストア・RPO/RTO | 同上（Neonのマネージド機能に依存） |
